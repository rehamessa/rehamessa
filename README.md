## 🧑‍💻 About Me

I work where operations meets data: taking the raw output of day-to-day business activity and turning it into numbers a team can trust enough to act on.

Most of that work happens before anyone opens a report. A dashboard is only as good as the definitions and the model behind it, so I spend my time on the parts that decide whether a number is right: how a KPI is defined, where the source data breaks, and what a measure should return when it does.

<br/>

## 🧠 How I Work

* **A KPI is a definition before it is a number.** Two teams can report the same SLA and mean different things. I settle what counts, what is excluded, and over which window before I write a line of DAX.
* **Metrics pull against each other.** A lower AHT can cost you FCR and CSAT. Pushing occupancy up puts SLA at risk. I build reports that show these side by side, so a win on one metric cannot hide a loss on another.
* **Data quality is part of the analysis, not a step before it.** Duplicates, gaps, and mismatched keys get traced to where they start and fixed in the query layer, so the report does not need a footnote explaining why the total is off.
* **If a report is built by hand twice, it should be automated.** I move recurring work into Power Query and SQL so the time goes into reading the numbers, not assembling them.
* **Start from the decision.** Before building anything I ask what the person will do differently once they have it. That question usually changes what gets built.

**Metrics I work with**

`AHT` · `SLA` · `CSAT` · `FCR` · `Adherence` · `Occupancy` · `Utilization` · `Productivity`
